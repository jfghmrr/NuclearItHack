# Доказательство работы без сети

Обработка на устройстве проверяется снаружи, без доверия к словам: разрешения нет, авиарежим не мешает, а прогон оставляет хэши и счётчики токенов.

## Как работает

- `INTERNET` и `ACCESS_NETWORK_STATE` сняты в манифесте через `tools:node="remove"`. Без разрешения приложение не может открыть сетевой сокет
- CI проверяет каждый собранный APK через `aapt2 dump permissions` и падает, если сетевое разрешение появилось
- Все модели лежат внутри APK. Файл языковой модели копируется на диск и сверяется с SHA-256, сети для этого не нужно
- В зависимостях нет телеметрии, аналитики и облачных SDK
- Шрифт встроен, плеер работает с локальным файлом, тексты лицензий лежат в приложении
- `metadata.json` каждого прогона содержит SHA-256 моделей, SHA-256 исходного файла и JSON, времена стадий и счётчики токенов языковой модели. По ним видно, какие файлы участвовали в прогоне и что модель действительно работала
- Экран «Приватность и разрешения» показывает то же на устройстве, см. [16. Модели, приватность и диагностика](16-verification.md)

## Как проверить

Перед началом: APK на компьютере, устройство подключено.

1. Выполните `aapt2 dump permissions <apk>` - в выводе нет `android.permission.INTERNET` и `android.permission.ACCESS_NETWORK_STATE`
2. Включите авиарежим - значок авиарежима виден в строке состояния
3. Импортируйте новую запись, которой не было в предыдущих шагах - обработка проходит до `DONE`, файл JSON появляется
4. Выполните `adb pull /sdcard/Download/Stenokot/meta/<имя>.metadata.json` - в поле `llm` есть `status`, `prompt_tokens`, `completion_tokens`, в поле `models` хэши
5. Откройте `src/mobile/android/gradle/libs.versions.toml` - в зависимостях нет сетевых и аналитических библиотек

Прогон в авиарежиме с полным APK проходил на эмуляторе на сборке `4eb4f0d`.

## Ограничения

- Отсутствие разрешения проверено на уровне пакета. Аудит нативных библиотек в репозитории не приложен
- Файлы моделей скачиваются при сборке из исходников, поэтому сеть нужна сборке, а не приложению
