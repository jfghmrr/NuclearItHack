# Продолжение после прерывания

Длинная запись переживает смерть процесса. Обработка продолжается с последнего чекпойнта, а не с начала, и приложение отличает «обработка прервана» от «результат потерян».

## Как работает

- Каждая стадия пишет результат на диск атомарно. Стадия считается пройденной, только если её файл существует вместе с файлами всех стадий до неё
- Чекпойнты: журнал `asr.jsonl` после каждого фрагмента, `diar.jsonl` после каждого окна, `job.json` при смене состояния. Оборванный хвост журнала отбрасывается и считается заново
- При следующем запуске записи задач сверяются с файлами на диске
- Прерванная задача на Главной: «Обработка прервалась», «Сохранён этап «{этап}». Продолжим с этого места» и кнопка «Продолжить». Экран задачи: «Продолжим с места остановки», «Система остановила обработку на этапе «{этап}». Готовые этапы сохранены»
- Если приложение открыто и 2 минуты ничем не занято, прерванная задача продолжается сама, один раз. Новый импорт важнее и идёт первым. Дальше решает пользователь: иначе файл, убивающий процесс, повторялся бы без конца
- После продолжения подсказка на экране обработки: «Продолжаем с сохранённой точки»
- Фрагмент, на котором распознавание падает дважды, пропускается. Окно диаризации, на котором процесс падает дважды, записывается пустым. Отметки остаются в `metadata.json`
- Если JSON уже записан, смерть процесса теряет только протокол: задача завершается, протокол получает `DEFERRED` и повтор
- Смена моделей или настроек отменяет всё после декодирования: старые журналы к новым моделям не подходят
- Смерть процесса `:llm` не задевает основной процесс. Причина определяется по записи системы: `LLM_DIED_OOM` или `LLM_DIED_NATIVE`
- Если файл задачи исчез и восстанавливать не из чего, это потеря результата, а не прерывание: задача показывается как ошибка
- Запись с микрофона, оборванная смертью процесса, восстанавливается по длине файла при следующем запуске и уходит в обработку

## Как проверить

Перед началом: Главная, `long.mp3` в `Download`.

1. Импортируйте `long.mp3` и дождитесь середины «Распознавание речи» - счётчик фрагментов идёт
2. Завершите процесс: `adb shell am force-stop ru.stenokot.app` - приложение закрылось
3. Откройте приложение - на Главной карточка «Обработка прервалась» с сохранённым этапом и кнопкой «Продолжить»
4. Подождите 2 минуты на Главной - обработка продолжается сама
5. Откройте карточку - счётчик не начался с нуля, подсказка «Продолжаем с сохранённой точки»
6. Снова выполните команду из шага 2 и откройте приложение - карточка «Обработка прервалась». Сама задача больше не продолжится
7. Нажмите «Продолжить» - обработка идёт с сохранённого места до конца, файл JSON появляется
8. Импортируйте `dialog1.mp3` и во время `RUNNING:LLM` завершите процесс модели:

```sh
adb root
adb shell kill -9 $(adb shell pidof ru.stenokot.app:llm)
```

Основной процесс жив, `dialog1.json` на месте и не изменился, протокол получает честный статус.

## Ограничения

- Команда `adb root` работает не на всех образах
- Автоматическое продолжение идёт только при открытом приложении: из фона система службу не запустит
- Фрагмент, который распознавался в момент смерти процесса, считается заново
- На эмуляторе проверено продолжение на стадии диаризации на ранней сборке `4531c82`. Шаги 1-7 на последней сборке не прогонялись
