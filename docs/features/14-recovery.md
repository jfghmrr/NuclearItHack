# Продолжение после прерывания

Длинная запись переживает смерть процесса. Обработка продолжается с последнего чекпойнта, а не с начала, и приложение отличает «обработка прервана» от «результат потерян».

## Как работает

- Каждая стадия пишет результат на диск атомарно. Стадия считается пройденной, только если её файл существует вместе с файлами всех стадий до неё
- Чекпойнты: журнал `asr.jsonl` после каждого среза, `diar.jsonl` после каждого окна, `job.json` при смене состояния. Оборванный хвост журнала отбрасывается и считается заново
- При следующем запуске записи задач сверяются с файлами на диске
- Прерванная задача показывает «Обработка прервалась», «Сохранён этап «{этап}». Продолжим с этого места» и кнопку «Продолжить»
- Когда приложение выходит на передний план, прерванная задача продолжается сама, один раз. Потом решает пользователь: иначе файл, убивающий процесс, повторялся бы без конца
- После продолжения подсказка: «Продолжаем с сохранённой точки»
- Срез, на котором распознавание падает дважды, пропускается. Окно диаризации, на котором падает процесс, записывается пустым. Отметки остаются в `metadata.json`
- Если JSON уже записан, смерть процесса теряет только протокол: задача завершается, протокол получает `DEFERRED` и повтор
- Смена моделей или настроек отменяет всё после декодирования: старые журналы к новым моделям не подходят
- Смерть процесса `:llm` не задевает основной процесс. Он делает одну попытку дописать протокол с готовых окон, пока есть бюджет. Причина смерти определяется по записи системы: `LLM_DIED_OOM` или `LLM_DIED_NATIVE`
- Если файл задачи исчез и восстанавливать не из чего, это потеря результата, а не прерывание: задача показывается как ошибка

## Как проверить

Перед началом: Главная, `long.mp3` в `Download`.

1. Импортируйте `long.mp3` и дождитесь этапа «Распознавание речи», счётчик примерно на середине
2. Завершите процесс: `adb shell am force-stop ru.stenokot.app` - приложение закрылось
3. Откройте приложение - на Главной карточка задачи, обработка продолжается сама
4. Откройте карточку - счётчик не начался с нуля, подсказка «Продолжаем с сохранённой точки»
5. Снова выполните команду из шага 2 и откройте приложение - на Главной карточка «Обработка прервалась» и кнопка «Продолжить»
6. Нажмите «Продолжить» - обработка идёт с сохранённого места до конца, файл JSON появляется
7. Импортируйте `dialog1.mp3` и во время `RUNNING:LLM` завершите процесс модели:

```sh
adb root
adb shell kill -9 $(adb shell pidof ru.stenokot.app:llm)
```

Основной процесс жив, `dialog1.json` на месте и не изменился, протокол дописывается с готовых окон или получает честный статус.

## Ограничения

- Команда `adb root` работает не на всех образах
- Автоматическое продолжение после смерти процесса идёт только при открытом приложении: из фона система запуск не разрешит
- Срез, идущий в момент смерти процесса, считается заново
