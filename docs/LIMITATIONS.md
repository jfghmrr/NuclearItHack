# Ограничения решения

## Поддерживаемые условия

- Android 10 и новее (`minSdk` 29), архитектура `arm64-v8a`
- Только CPU. GPU и NPU не используются
- Форматы: MP3, WAV, M4A, OGG, FLAC, включая FLAC в контейнере Ogg. Берётся первая звуковая дорожка файла
- Основной язык русский. Английский определяется автоматически, только при уверенном перевесе
- От 1 до 8 говорящих на запись. У записей с узкой полосой, например созвонов, предел 4
- Целевая среда: стандартный эмулятор ARM с 4 ГБ RAM. Запас памяти рассчитан на неё
- Свободное место на устройстве сверх размера APK: копия языковой модели 378 МиБ, а на каждую запись размер файла, 46 КБ на секунду звука и резерв 64 МиБ
- Интерфейс только на русском. Текст реплик остаётся на языке записи

## Известные ограничения

Распознавание:

- GigaAM e2e сама ставит пунктуацию и нормализует текст. Модель может исправлять падежи и заменять редкие слова: настройкой это не отключается, а приложение текст после распознавания не правит
- Модель со знаками уступает варианту без знаков в чистом WER: на открытом сравнении onnx-asr, подмножество Russian LibriSpeech, 6,94 % против 4,39 %, машина автора сравнения. Вариант без знаков не подходит: пунктуация входит в требования. На наших записях цена выбора не измерена
- Silero VAD может пропускать высокие и мультяшные голоса и принимать инструменты за речь. Поэтому он нужен только для разрезов и пропуска пауз от 2 секунд. Речь внутри такой паузы может быть потеряна
- Поведение модели на музыке и заставках не измерено
- У токенов GigaAM есть только начало, сетка 40 мс. Конец слова приложение оценивает: 70 мс на букву, от 120 до 600 мс
- Срез, на котором распознавание падает дважды, пропускается. Его текста в файле нет, отметка `SKIPPED_SEGMENT:<номер>` остаётся в `metadata.json`
- Язык определяется один раз на файл по трём пробным срезам: смешанная запись идёт одной моделью. Пороги не откалиброваны

Говорящие:

- Одноканальный ASR даёт один поток слов: при наложении речи каждое слово получает одного говорящего, перекрытие только помечается. Текст двух голосов не разделяется
- Параметры диаризации получены на английских совещаниях. На русских записях они не откалиброваны, DER не измерен
- Русский язык не заявлен в обучении обеих моделей говорящих
- Говорящий, у которого речи меньше порога, поглощается ближайшим. Порог - 2 % всей речи, но не меньше 2 и не больше 6 секунд. Участник с одной короткой фразой может исчезнуть
- Лишние кластеры сверх предела сливаются с ближайшими по голосу
- Окно диаризации, на котором процесс падает, записывается пустым с отметкой `SKIPPED_WINDOW:<номер>`, его слова получают говорящего из соседних интервалов
- Номера говорящих действуют в пределах одной записи

Языковая модель:

- Qwen3-0.6B маленькая, отдельных метрик качества на русском нет. Протокол всегда подписан как черновик
- Бюджет времени не больше 90 секунд, поэтому на длинной записи протокол покрывает только часть окон и получает статус частичного. Покрытие на длинных файлах не измерено
- Первое окно получает попытку даже на короткой записи, поэтому там `RTF_full` может оказаться заметно больше `RTF_core`
- Если следующий файл приходит сразу, модель уступает ему: протокол откладывается и запускается один раз после 30 секунд простоя. Если проверка заканчивается раньше, токенов модели в этом прогоне не будет
- Сразу после установки файл модели ещё копируется. Обработка не ждёт копию, ждёт только стадия протокола, статус `WAITING_MODEL`
- Для запуска нужно 650 МиБ свободной памяти. Иначе протокол пропускается, статус `SKIPPED_LOW_MEMORY`
- Повтор один. Если пользователь сам отменил протокол, повтора нет

Обработка:

- Отмена срабатывает на безопасной границе: между срезами распознавания и между окнами диаризации. Нативный вызов на окне неделим, поэтому в диаризации отмена может ждать конца окна
- Оценка времени до первой подходящей записи на устройстве примерная. Запись короче 10 секунд замером не считается
- Автоматическое продолжение после смерти процесса одно. Дальше решает пользователь кнопкой «Продолжить»: иначе файл, убивающий процесс, повторялся бы без конца
- Android 15 ограничивает службы обработки 6 часами в сутки. При срабатывании лимита приложение сохраняет чекпойнт и показывает прерывание `FGS_TIMEOUT`

Данные и размер:

- Файл JSON в `Download/Stenokot/` виден другим приложениям с доступом к общей памяти
- Копия исходного файла и `pcm16k.wav` остаются во внутренней папке, пока пользователь не удалит запись
- APK содержит все модели, сумма весов 770 МиБ. Итоговый размер не измерен

Измерения:

- WER и DER не измерены
- `RTF_core` и `RTF_full` готового APK не измерены. Есть только замер отдельных стадий на эмуляторе, см. [TEST_RESULTS.md](TEST_RESULTS.md)
- Память на записи 60 минут не измерена
- Телефона в работе не было. Всё проверялось на эмуляторе

## Что не входит в текущую версию

- Дообучение моделей
- Запись с микрофона
- Работа в реальном времени
- Редактирование текста и переименование говорящих
- Говорящие между записями
- Разделение наложенной речи на отдельные голоса
- Вычисления на GPU и NPU
- Сборка для `x86_64`

## Риски демонстрации

- Скорость на стенде проверки неизвестна: образ, число vCPU и хост организаторы не сообщили
- Если стенд запускает ARM через трансляцию на x86, скорость может оказаться намного ниже замеров на Mac M4
- Первый запуск идёт сразу после установки большого APK, файловый кэш пуст
- Системное окно выбора файла - чужое окно. На незнакомом образе оно может выглядеть иначе. Поэтому есть запуск по адресу файла и список найденных аудио
- Эмулятор может завершить тяжёлый процесс при нехватке памяти. Поэтому модели загружаются по очереди, а стадии пишут чекпойнты
