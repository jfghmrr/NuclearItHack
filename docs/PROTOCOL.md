# Протокол обмена

Как файл попадает в приложение, что выходит наружу и в каком виде. Подробности для автоматической проверки собраны в [AUTOMATION.md](AUTOMATION.md).

## Цели

- Принять аудиофайл любым штатным способом Android и без касаний, если файл отправлен командой.
- Выдать один контрактный JSON на файл в известное место, как только он готов, не дожидаясь протокола.
- Дать проверяющему однозначный признак состояния на экране и в журнале.

## Вход

| Способ | Пример |
|---|---|
| Системный выбор файла | Кнопка «Импорт аудио» |
| «Открыть с помощью», «Поделиться» | `ACTION_VIEW`, `ACTION_SEND`, `ACTION_SEND_MULTIPLE` с `content://` |
| Команда | `adb shell am start -a android.intent.action.VIEW -t audio/mpeg -d file:///sdcard/Download/a.mp3 -p ru.skvor.app` |
| Запись в приложении | Кнопка «Записать», WAV 16 кГц моно |

Форматы: MP3, WAV (включая RF64 и файлы больше 4 ГБ), M4A, OGG, FLAC. Следующий файл можно отправить в уже открытое приложение той же командой: задачи идут в очередь по одной. Адрес `file://` внутрь закрытых каталогов приложения и `content://` его собственного провайдера отклоняются до обработки.

## Выход

Контрактный файл появляется в `Download/Skvor/<имя>.json` сразу после проверки валидатором, до запуска протокола:

```json
{
  "transcript": [
    {"speaker_id": "speaker_1", "start_ms": 1200, "end_ms": 3237, "text": "Алло, всем привет!"},
    {"speaker_id": "speaker_2", "start_ms": 7152, "end_ms": 9008, "text": "Это я так не хотел, хотел сам потестить."}
  ]
}
```

Правила файла:

- Только поле `transcript` с четырьмя полями у каждой реплики, без лишних ключей.
- Время в миллисекундах от начала записи, `0 <= start_ms < end_ms <= длительность`, реплики отсортированы по `start_ms`.
- Говорящие `speaker_1..speaker_K` без пропусков, номера по первому появлению. Реплики разных говорящих могут пересекаться по времени.
- Тишина даёт `{"transcript":[]}`.
- Файл записывается целиком и атомарно. Файл, не прошедший валидатор, не записывается никогда.
- Ручная правка реплики переписывает тот же файл после повторной проверки. Без правок байты не меняются.

Служебные файлы лежат отдельно, чтобы поиск `*.json` в основной папке находил только контрактные:

| Файл | Что внутри |
|---|---|
| `Download/Skvor/meta/<имя>.metadata.json` | Версии и SHA-256 моделей, SHA-256 входа и JSON, время стадий, `rtf_core`, `rtf_full`, пик памяти, предупреждения |
| `Download/Skvor/meta/<имя>.protocol.json` | Протокол: разделы с темой и временем, пункты `decision`, `action`, `question` со ссылкой на номер реплики |

## Состояние

Строка `txt_status` есть на каждом экране и дублируется в logcat с тегом `PIPELINE`: `IDLE`, `QUEUED`, `RUNNING:<STAGE>`, `TRANSCRIPT_READY`, `RUNNING:LLM`, `DONE`, `DONE_LLM_FAILED`, `DONE_META_FAILED`, `FAILED:<CODE>`, `CANCELLED`. JSON уже лежит на месте при `TRANSCRIPT_READY` и всех `DONE*`.

## Ошибки и восстановление

- Ошибка входа или нехватка ресурсов дают `FAILED:<CODE>` без модальных окон, приложение остаётся живым.
- Стадии пишут контрольные точки. После остановки процесса задача продолжается с последней точки, а новый файл идёт первым.
- Сбой протокола после JSON не трогает стенограмму: статус `DONE_LLM_FAILED`.

## Совместимость

Android 10 и новее, `arm64-v8a`. Сети нет: в манифесте нет `INTERNET` и `ACCESS_NETWORK_STATE`, это проверяет сборка в CI.

## Пример

```bash
adb install -r -g skvor.apk
adb push meeting.mp3 /sdcard/Download/meeting.mp3
adb shell am start -a android.intent.action.VIEW -t audio/mpeg \
  -d file:///sdcard/Download/meeting.mp3 -p ru.skvor.app
adb shell 'until [ -f /sdcard/Download/Skvor/meeting.json ]; do sleep 1; done'
adb pull /sdcard/Download/Skvor/meeting.json
```
