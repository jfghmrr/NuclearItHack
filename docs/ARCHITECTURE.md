# Архитектура

## Контекст

Приложение работает на одном устройстве Android без сети. Вход - аудиофайл или запись с микрофона. Выход - контрактный JSON, служебные данные и экран результата.

Проверка идёт автоматически на эмуляторе ARM с 4 ГБ RAM, образ и хост неизвестны. Скорость считается от загрузки файла до файла экспорта. Отсюда главные решения: стадии строго по очереди, JSON раньше языковой модели, на пути автоматики нет диалогов, прогрев моделей до приёма файла.

## Компоненты

| Модуль | Назначение |
|---|---|
| `:core` | Чистый Kotlin: контракт и валидатор, нарезка на фрагменты, повторное распознавание пауз, склейка фрагментов, определение языка, книга говорящих, уточнение говорящих по фразам, слияние, окна и пределы языковой модели, протокол, состояния и ошибки, формулы скорости. Тесты на JVM |
| `:app` | Интерфейс Compose, очередь и стадии, служба обработки, служба записи, хранилище задач, декодер, обёртки sherpa-onnx, служба языковой модели |
| `:engine-llm` | Сборка llama.cpp, мост JNI, генерация с грамматикой GBNF, отмена |

| Процесс | Что в нём работает |
|---|---|
| Основной | Интерфейс и все стадии до JSON. Служба переднего плана типа `dataSync`, с Android 15 `mediaProcessing`. По сигналу о шестичасовом лимите служба переходит на `specialUse` |
| Основной, запись | Служба переднего плана типа `microphone`, только пока идёт запись |
| `:llm` | Только языковая модель, обычная связанная служба. Файлы пишутся атомарно, поэтому процесс можно завершить в любой момент |

```text
Импорт -> Предпроверка -> Декодирование -> VAD -> Язык -> ASR -> Диаризация окнами -> Уточнение по фразам
       -> Слияние -> Проверка JSON -> Download/Skvor/<имя>.json -> пауза 3 с -> LLM в процессе :llm -> Протокол
```

Каждая стадия читает вход с диска и пишет выход на диск. Модель стадии закрывается до начала следующей. Исключение одно: распознаватель может ждать следующий файл уже загруженным, если свободно не меньше 1450 МиБ.

```text
filesDir/jobs/<uuid>/
    job.json          состояние задачи, замена атомарная
    source.<ext>      копия импортированного файла. Файл больше 256 МБ с постоянным доступом читается на месте
    pcm16k.wav        единая шкала времени
    waveform.bin      огибающая для плеера
    vad.json          фрагменты записи
    lang.json         язык файла
    asr.jsonl         журнал распознавания по фрагментам
    diar.jsonl        журнал окон диаризации
    turns.json        интервалы говорящих после сшивки и уточнения
    merged.json       реплики
    transcript.json   контрактный файл
    llm_windows.jsonl журнал ответов языковой модели
    protocol.json     протокол
    metadata.json     доказательства прогона
    metrics.jsonl     замеры стадий
    llm_stats.json    счётчики языковой модели
filesDir/speed.json         скорость этого устройства для оценки времени
filesDir/recordings/        записи с микрофона
noBackupFilesDir/models/<версия>/    копия файла языковой модели, отметка llm.READY
Download/Skvor/<имя>.json
Download/Skvor/meta/<имя>.metadata.json, <имя>.protocol.json
```

## Основные решения

| Решение | Причина |
|---|---|
| ASR раньше диаризации | Ошибка диаризации не задевает текст, а резка по говорящим портит распознавание: на перекрытиях WER рос на 2,9-4,5 пункта |
| Стадии строго последовательны | Две тяжёлые модели одновременно небезопасны на 4 ГБ |
| Одна тяжёлая задача, порядок по поступлению | Порядок предсказуем, модели не встречаются |
| JSON записывается до LLM | Сбой модели не теряет результат, скорость основного пути от неё не зависит |
| `DONE` последним | Кто дождался `DONE`, уже находит в `meta/` и протокол, и замеры. Сбой их записи виден как `DONE_META_FAILED` |
| Пауза 3 с после JSON | Автоматике нужно время увидеть файл до старта тяжёлой модели |
| LLM в отдельном процессе | Смерть процесса возвращает память и не трогает интерфейс |
| Язык по алфавиту текста GigaAM | Лишняя модель не нужна, русский файл решается на трёх пробных фрагментах |
| Диаризация окнами по 5 минут | Нативный метод держит весь сигнал в куче и строит квадратичную матрицу |
| Говорящие пересобираются по фразам | Нативная кластеризация неустойчива на отдельных файлах. Фразы, уже найденные распознаванием, дают чистые отпечатки голоса |
| Чекпойнты после каждого фрагмента и окна | Длинная задача переживает смерть процесса |
| Единая шкала `pcm16k.wav` | Распознавание, диаризация и плеер читают один файл. Громкость приводится к -23 дБFS только при чтении |
| Модели внутри APK | Основная работа без сети. ONNX читаются из assets, импорт работает сразу после установки |
| Копия языковой модели в простое | Копия не конкурирует с распознаванием: пока идёт задача, она стоит |
| Хранение в файлах | Запросов нет, база данных лишняя |
| Текст модели никто не правит | Текст должен оставаться дословным |
| Готовые веса без дообучения | Открытых русских разговоров с проверенным эталоном и ясной лицензией нет |

Потоки распознавания и диаризации: `max(2, min(4, производительные ядра, ядра - 1))`.

### Диаризация и говорящие

1. Окна по 5 минут с нахлёстом 10 с. Хвост короче 30 с присоединяется к последнему окну
2. Настройки по длине записи: до 120 с шаг сегментации 0,25 и порог 0,6, до 330 с шаг 0,5 и порог 0,7, длиннее шаг 0,25 и порог 0,8. Порог растёт с числом отпечатков в окне
3. У кластера окна отпечаток TitaNet по чистой речи без наложений, от 1,5 до 30 с
4. Книга говорящих связывает кластеры окон по косинусу 0,6. Два кластера, звучащие вместе от 500 мс, одним говорящим не станут. Малый кластер с непохожим голосом остаётся
5. Уточнение: слова с говорящими режутся на фразы по концу предложения, смене говорящего и паузе от 700 мс, до 10 с. Из фразы вычитается наложение, фраза с чистым звуком от 1,5 с получает отпечаток до 6 с
6. Фразы группируются средней связью при косинусе 0,55, группы с центроидами от 0,65 сливаются, группы до 10 с чистой речи уходят к ближайшей. Затем один проход переназначения
7. Решение пишется только в интервалы говорящих. Слияние идёт без изменений, поэтому слово не может потеряться, измениться или повториться
8. Фраз с отпечатком меньше двух, сбой уточнения или монолог из одного окна с одним кластером: остаются интервалы диаризации

На записи длиннее 1500 фраз группируются 1500 равномерно выбранных, остальные назначаются проходом. Память уточнения ограничена матрицей 1500 на 1500, около 9 МБ.

### Память

Перед каждой стадией свободная память сверяется с бюджетом стадии. Ниже бюджета обработка не останавливается, появляется предупреждение `LOW_MEMORY`. Исключение: языковая модель не запускается при свободных меньше 650 МиБ, статус `SKIPPED_LOW_MEMORY`.

| Стадия | Бюджет, МиБ |
|---|---:|
| Декодирование | 170 |
| Поиск речи | 190 |
| Определение языка, распознавание | 850 |
| Диаризация | 450 |
| Слияние | 100 |
| Проверка и запись JSON | 50 |
| Языковая модель | 650 |

Это бюджеты, а не замеры. Английская модель на Honor давала пик 1,41 ГБ всего процесса. Замеры в [TEST_RESULTS.md](TEST_RESULTS.md).

## Состояния задачи

```text
Queued -> Running(IMPORT..VALIDATE) -> TranscriptReady -> [WaitingModel] -> Running(LLM) -> Done
WaitingModel -> Done(DEFERRED)                               новый импорт, пока копируется модель
Running -> Paused -> Running                                 перегрев
Running -> Interrupted -> Running                            продолжение с чекпойнта
Running -> Failed                                            до появления JSON
Running -> Cancelled                                         отмена пользователем
Queued -> Cancelled                                          отмена в очереди
Failed, Cancelled, Interrupted -> Queued                     запуск заново
TranscriptReady, Running(LLM) -> Done(LlmStatus)             никогда не Failed: JSON уже есть
Done(DEFERRED или SKIPPED_BY_BUDGET) -> Running(LLM) -> Done один повтор после 30 с простоя
```

| Состояние | `txt_status` |
|---|---|
| Задачи нет | `IDLE` |
| `Queued`, ожидание другой задачи | `QUEUED` |
| `Running`, пауза из-за перегрева | `RUNNING:<STAGE>` |
| JSON сохранён, 3 с до старта LLM | `TRANSCRIPT_READY` |
| `WaitingModel` | `WAITING_MODEL` |
| `Done` | `DONE` |
| `Done`, модель завершилась с ошибкой | `DONE_LLM_FAILED` |
| `Done`, протокол или замеры не опубликованы | `DONE_META_FAILED` |
| Нет речи | `DONE`, предупреждение `AUDIO_EMPTY` |
| `Failed`, `Interrupted` | `FAILED:<CODE>` |
| `Cancelled` | `CANCELLED` |
| Экран записи с микрофона | `RECORDING` |

Стадии `<STAGE>`: `IMPORT`, `DECODE`, `VAD`, `LANG_ID`, `ASR`, `DIARIZE`, `MERGE`, `VALIDATE`, `LLM`. Прерывание без известной причины: `FAILED:INTERRUPTED`.

Итог языковой модели `LlmStatus`: `APPLIED`, `PARTIAL`, `DEFERRED`, `CANCELLED_BY_NEW_JOB`, `SKIPPED_BY_BUDGET`, `SKIPPED_LOW_MEMORY`, `FAILED`. Остановка новым импортом записывается как `DEFERRED`, `CANCELLED_BY_NEW_JOB` ставится, когда протокол остановил сам пользователь.

После смерти процесса запись задачи сверяется с файлами на диске. Стадия считается пройденной, только если её результат есть вместе с результатами всех стадий до неё. Если JSON записан, задача завершается с протоколом `DEFERRED`. Если нет, она становится прерванной и продолжается с первой незавершённой стадии.

## Правила и инварианты

- Текст ASR после распознавания не редактируется. Слияние перемещает целые слова и не меняет их текст
- Повторное распознавание паузы только добавляет слова в промежуток. Старые слова не меняются, не удаляются и не переставляются
- Языковая модель выбирает вид пункта и номер реплики. Текст пункта, говорящего и время копирует код. Грамматика допускает только настоящие номера реплик окна
- Контрактный JSON записывается до старта языковой модели и от неё не зависит. При провале проверки он не записывается никуда
- Сбой языковой модели заканчивается `Done(LlmStatus)` и не делает задачу неудачной
- Новый импорт останавливает работающую языковую модель в пределах 1 с
- Прогресс настоящий: только реальные счётчики, значения внутри этапа обновляются не чаще раза в секунду

Слияние:

- Слова не теряются и не меняются, каждое входит ровно в одну реплику
- Время: `0 <= start_ms < end_ms <= длительность + 50 мс`
- Реплики отсортированы по `start_ms`, реплики разных говорящих могут пересекаться
- Говорящие идут как `speaker_1..speaker_K` без пропусков, по первому появлению
- Результат детерминирован, знак препинания не уходит от своего слова

Крайние случаи:

- Тишина даёт `{"transcript":[]}` и предупреждение `AUDIO_EMPTY`
- Неподдерживаемый или повреждённый файл отсеивается на предпроверке, до загрузки моделей
- Фрагмент, на котором распознавание падает дважды, пропускается с отметкой `SKIPPED_SEGMENT:<номер>`. Окно диаризации, которое падает дважды, записывается пустым, отметка `SKIPPED_WINDOW:<номер>`
- Если интервалов говорящих нет совсем, текст остаётся, а реплики получают одного говорящего

## Языковая модель

- Окно 450 токенов, граница всегда между репликами. Окна с редкой речью, ниже 30 слов в минуту, пропускаются
- Окна идут так, что любая начальная часть покрывает запись равномерно: сначала середина, затем середины половин
- Пределы: не больше 60 окон на запись, 45 минут на стадию от конца загрузки, 180 с на окно, 5 минут на загрузку модели. Они защищают только от очень длинных записей и зависшей генерации
- Если обработаны все окна, `APPLIED`. Если часть, `PARTIAL`. Если ни одного, `SKIPPED_BY_BUDGET`
- Запрос: `n_ctx` 1024, ответ до 64 токенов, `temperature` 0,2, `top_k` 20, `top_p` 0,9, `seed` 42. Не больше трёх пунктов на окно
- Вид пункта подтверждается словами реплики: решение и поручение прямым оборотом, вопрос знаком вопроса. Лучше пропустить пункт, чем показать ложный
- `DEFERRED` и `SKIPPED_BY_BUDGET` получают один повтор после 30 с простоя
