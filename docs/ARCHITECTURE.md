# Архитектура решения

## Контекст

Приложение работает на одном устройстве Android без сети. Вход: аудиофайл. Выход: контрактный JSON, служебные данные и экран результата. Устройство проверки: стандартный эмулятор ARM, 4 ГБ RAM.

## Компоненты

| Модуль | Назначение |
|---|---|
| `:core` | Чистый Kotlin: контракт, валидатор, слияние, ресемплер, состояния, логика протокола. Тесты идут на JVM |
| `:app` | Интерфейс Compose, служба конвейера, декодер, обёртки sherpa-onnx, служба LLM |
| `:engine-llm` | llama.cpp, JNI, генерация с грамматикой GBNF |

```text
Импорт -> Предпроверка -> Декодирование -> VAD -> Язык -> ASR -> Диаризация окнами -> Слияние
       -> Проверка JSON -> Download/Stenokot/<имя>.json -> пауза 3 с -> LLM в процессе :llm -> Протокол
```

## Основные технические решения

| Решение | Причина |
|---|---|
| ASR раньше диаризации | Ошибка диаризации не затрагивает текст, а резка по говорящим портит распознавание |
| Стадии строго последовательны | Совместная загрузка моделей небезопасна на 4 ГБ |
| JSON записывается до LLM | Сбой LLM не теряет результат, скорость основного пути не зависит от LLM |
| LLM в отдельном процессе | Смерть процесса возвращает память и не трогает интерфейс |
| Диаризация окнами по 5 минут | Память не зависит от длины записи |
| Чекпойнты после каждого чанка | Длинная задача переживает завершение процесса |
| Хранение в файлах | Запросов нет, база данных лишняя |
| Foreground Service | Работа при выключенном экране |

## Зависимости

sherpa-onnx v2.0.1, llama.cpp v0.9.0, Jetpack Compose, Media3, kotlinx-serialization, kotlinx-coroutines. Состав моделей в [MODEL_MANIFEST.md](MODEL_MANIFEST.md).

## Безопасность и приватность

Разрешений `INTERNET` и `ACCESS_NETWORK_STATE` нет. Обработка выполняется только на устройстве. Подробности в [SECURITY.md](SECURITY.md).
